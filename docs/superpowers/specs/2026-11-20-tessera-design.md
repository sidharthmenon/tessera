# Tessera — Rust media server — Design + Phase 1 Plan

Working name **Tessera** (own name and look). Rename freely.

## Context

User runs LED/event shows on a commercial media server. Wants an own cross-platform media server in Rust: multiple displays, multiple logical screens with mapping/layout, multi-layer composition, cue management, PGM/PVW workflow. Purpose: **run own shows** — reliability and real hardware over polish. Platforms: **macOS + Windows**. V1 also needs live inputs, transitions/effects, remote/multi-node — split into 3 phases, each usable on its own.

## Design

### Goals / non-goals / anti-goals
- Goals (Phase 1): screen management (outputs ↔ screens ↔ mapping ↔ layout), N fullscreen outputs on N displays, multi-layer per screen, media (image, video+audio, test patterns), cue grid with groups, PVW→PGM Take with transitions, per-layer effects, project save/load.
- Non-goals Phase 1: live inputs (Phase 2), network/multi-node (Phase 3), PPT, Spout/Syphon, playlists, warping/edge-blend, 8K/HAP GPU codecs, EDID/LED-processor control.
- Anti-goals: UI crash blacks out screens; video restarts/stutters on Take; show file lost to crash; output glitches when operator edits PVW.

### Approach (user picked B)
- **A. One binary egui+wgpu, 2 modes** — simplest, but UI crash kills outputs.
- **B. Engine process + Tauri web UI (chosen)** — render engine is separate headless process; UI crash can't black out screens. Cost: TS in stack, protocol between processes.
- **C. GStreamer** — heavy runtime to bundle, less GPU/mapping control.

### Architecture

```
┌──────────── Tauri app (controller) ────────────┐        ┌──────── engine (render node) ────────┐
│ Svelte/TS UI  ──invoke──▶ Rust backend          │  WS    │ tokio: axum WS + MJPEG HTTP          │
│  panels, cue grid,      owns Show (truth),      │ ─────▶ │ main thread: winit + wgpu            │
│  screen mgmt dialog     undo, file IO, autosave │ JSON   │  player pool (ffmpeg decode threads) │
│  <img src=mjpeg> ◀──────────────────────────────┼─HTTP── │  compositor → output windows         │
└─────────────────────────────────────────────────┘        │  cpal audio mixer                    │
                                                           └──────────────────────────────────────┘
```

- **Controller = Tauri Rust backend.** Owns `Show` (single source of truth), undo stack, file IO, spawns engine as sidecar, holds WS client. Frontend sends intents via `invoke`, receives full `Show` JSON via `show-changed` event after each mutation (show is KBs; no diffing).
- **Engine = separate binary `tessera-engine`.** Stateless-ish renderer: holds config + PVW scene + PGM scene + transition. Same binary becomes Phase 3 remote node. If engine dies, controller restarts it and re-sends config + scenes. If UI dies, engine keeps last state on outputs.
- **Previews:** engine serves `GET /preview/{pgm|pvw}.mjpg?token=…` (multipart MJPEG, ~15 fps, ~960 px wide layout view). Frontend just `<img src>` — native in WKWebView and WebView2, zero JS decode. Readback only while a client is connected.
- **Security:** engine binds `127.0.0.1` only; controller passes random token via env; WS + MJPEG require it.

### Data model (`crates/show`)
- `Output { id, name, node: String /* "local" in P1 */, target: Display{monitor_name, monitor_pos} | Window{x,y,w,h}, width, height, brightness }` — `Window` target = windowed output for dev and confidence monitors. Status Bound/Unbound computed by engine from monitor match (name, then position).
- `Screen { id, name, width, height, layout_pos: (x,y) }` — logical canvas (e.g. LED wall 3840×1080).
- `Mapping { screen_id, src: Rect /*screen px*/, output_id, dst: Rect /*output px*/ }` — one screen may span many outputs; many slices cover irregular LED shapes.
- `Cue { id, name, slot: u32, layers_by_screen: Map<ScreenId, Vec<Layer>>, transition: { kind: Cut|Fade|WipeLeft|WipeRight, duration_ms } }`; `Group { id, name, cues }`.
- `Layer { id: Uuid, name, source: Media(MediaId)|TestPattern(Bars|Grid|Gradient|Solid(rgba)), rect, opacity, brightness, contrast, saturation, volume, playback: Loop|Once|HoldLast, visible }`.
- `MediaItem { id, path (relative to show folder when inside it), kind, width, height, duration_ms, has_audio, thumb }` — probed by engine (keeps FFmpeg out of the Tauri binary).
- Show file: JSON `.tshow`, atomic write (tmp + rename). Autosave `<file>.autosave` debounced 2 s. Undo/redo: snapshot stack of `Show` clones, cap 100.

### Engine protocol (serde JSON over WS; TS types generated by `ts-rs`)
- To engine: `SetConfig{outputs,screens,mappings}`, `SetPreview{scene}`, `SetProgram{scene}` (live tweak, no transition), `Take{transition}`, `Transport{bus: Pgm|Pvw, layer: Option<Id>, action: Play|Pause|Stop|Restart}`, `SetMasterVolume`, `ListMonitors`, `Probe{path}`, `Identify{output_id}`.
- From engine: `Monitors[..]`, `OutputStatus[..]`, `Probed{..}`, `TakeDone`, `Positions{layer_id → ms}` (5 Hz), `Error{..}`.
- `Scene` = `Map<ScreenId, Vec<Layer>>` (a cue's layers).

### Show requirements (user answers)
- **Load:** 4K H.264/HEVC + ProRes (incl. 4444 alpha), several layers at once. Hardware decode is Phase 1 work.
- **Shared media keeps running:** same media on same screen at same layer index carries across Take seamlessly.
- **Take = all screens at once.** A cue only touches screens it defines; other screens keep PGM content.
- **First show on macOS.** Windows verified later, before its first use.

### Key behaviors
- **Player pool, refcounted by PVW, PGM, and outgoing-transition scenes.** Player resolution happens at `SetPreview`: an incoming layer reuses the PGM player when `(screen_id, MediaId, layer index)` matches; otherwise new player. So PVW truthfully shows continuity, and Take never restarts shared media. Players freed when no scene references them. Changing rect/effects never touches the player.
- **New players in PVW cue paused on first frame; start on Take** (my call — cue starts when operator fires it). Shared/running players keep running.
- **Take merge:** new PGM = for each screen, cue's layers if cue defines that screen (`layers_by_screen` key present; empty vec = explicit black), else existing PGM layers. Transition runs only on screens that change.
- **Cue flow:** click cue = load to PVW; `Space`/GO = Take with cue's transition; `→` = load next slot to PVW; double-click = load + Take. Groups = tabs of grid.
- **Compositor per frame:** for each bus needed (PGM always; PVW only if previewed): per Screen render layers bottom→top into screen texture (one pipeline: YUV420P/NV12 or RGBA sampling + rect + opacity/brightness/contrast/saturation). Transition: render outgoing + incoming screen textures, mix in transition shader. Per Output: draw each mapping quad (src rect of PGM screen texture → dst rect), apply output brightness. Preview: draw screens at `layout_pos` into downscaled layout texture → readback → JPEG.
- **Video:** `ffmpeg-next` decode thread per player. **Hardware decode first:** FFmpeg `hwaccel` VideoToolbox (macOS; ProRes incl. 4444 + HEVC + H.264), D3D11VA (Windows), software fallback. Frames → `av_hwframe_transfer_data` → upload planes; formats: NV12 (8-bit 4:2:0), P010 (10-bit), BGRA8 / RGBA16 (alpha, ProRes 4444), RGBA8 (sws fallback). Shader converts YUV→RGB (BT.709, limited/full range from stream) and blends premultiplied alpha. Frame chosen by `pts <= now - start` on engine monotonic clock. Loop = seek 0 at EOF; decoder runs ahead with small frame queue (3–4) and pre-rolls loop start. `ponytail:` CPU transfer + upload; **zero-copy** (`CVMetalTextureCache` → `wgpu` Metal `create_texture_from_hal`) built only if spike shows transfer path misses frame rate.
- **Audio:** decode + `swresample` to device format, per-player ring buffer, mixed in `cpal` callback with layer volume × master. Video timed to wall clock. `ponytail:` no audio-clock slaving, drift ~ppm; resample-based sync if long clips drift.
- **Outputs:** one winit window per Output; `Display` = borderless fullscreen on matched monitor (macOS: simple fullscreen, no Spaces animation), `Window` = decorated window. macOS engine uses `ActivationPolicy::Accessory` (no Dock icon). Render all windows in one loop; frame pacing via primary output vsync (Fifo) and Mailbox/Immediate on others. `ponytail:` single render thread; per-output threads if multi-refresh-rate pacing judders.

### Decided by me (user can override)
LED walls fed by several GPU outputs: recommend spanned display (NVIDIA Mosaic / AMD Eyefinity / one big macOS display) with one Display output, so joins are frame-locked; separate windows per output may differ by a frame. **Svelte 5 + Vite + TS** for frontend; **Tauri 2** stable (3 is alpha); **winit 0.30** (0.31 beta); **wgpu 30**; **ffmpeg-next 9.x** against Homebrew FFmpeg 9 (fallback: `brew install ffmpeg@7` + `FFMPEG_DIR`); **axum 0.8** for WS+MJPEG; **cpal**; **image** (decode + JPEG encode); **ts-rs**. Audio included in Phase 1 (T1 has volume). Windowed output target added for dev/testing.

### Left to the builder
Exact shader structure, WGSL layout, UI component split, styling (dark pro theme in spirit of T1, not a copy), thumbnail size, MJPEG quality.

### Phase 2 outline — live inputs
New `Layer.source = Capture{device}` via FFmpeg avdevice (`avfoundation` / `dshow`) reusing the video player path; device list via avdevice (fallback `nokhwa` if enumeration is poor). NDI receive as source + NDI send per output (readback output texture), runtime loaded with `libloading`. Own detailed plan after Phase 1 runs.

### Phase 3 outline — remote / multi-node
Engine `--listen 0.0.0.0:7400 --token …`; controller connects to N engines; each engine renders only outputs with its `node`. Clock offset via ping (median NTP-style); `Take`/`Transport` carry `at = controller_time + 100 ms`. Media check per node (path+size+hash), push missing over HTTP. External control: OSC (`rosc`) + HTTP API on controller (GO, load cue N) for Companion/Stream Deck. Own detailed plan later.

## Phase 1 implementation plan

### Layout
```
Cargo.toml                    workspace: crates/show, crates/engine, app/src-tauri
crates/show/src/{lib,model,protocol,cue,geom}.rs
crates/engine/src/{main,net,gpu,compositor,player,audio,outputs,preview,probe}.rs
crates/engine/src/shaders/{layer,transition,map}.wgsl
crates/engine/tests/{render,decode}.rs  + tests/fixtures/clip.mp4 (1 s 64×64 h264+aac)
app/src-tauri/src/{main,controller,engine_client,files}.rs, tauri.conf.json (externalBin sidecar)
app/src/{App.svelte, lib/bindings/*.ts (generated), lib/panels/*.svelte}
docs/superpowers/specs/2026-11-20-tessera-design.md   (design section above)
```

### Steps
0. **Setup:** save design to `docs/superpowers/specs/`, then expand these steps into bite-size tasks with superpowers:writing-plans before coding. `rustup update stable` (1.87 likely below wgpu 30 MSRV); `brew install pkgconf`; `git init`; save design doc to `docs/superpowers/specs/`. Windows notes in README: BtbN FFmpeg shared build + `FFMPEG_DIR`.
1. **Spike (de-risk first, throwaway, macOS):** engine opens 2 windows (one fullscreen on 2nd monitor if present + 1 windowed), decodes with ffmpeg-next + VideoToolbox, renders to both at vsync. Measure: **4 simultaneous 4K layers** (2× HEVC, 1× H.264, 1× ProRes 4444 alpha) with transfer+upload path — target 60 fps without drops. Confirms ffmpeg-next ↔ FFmpeg 9 build, multi-window pacing, macOS simple fullscreen. If target missed: zero-copy CVMetalTextureCache moves into step 4. Test clips generated with `ffmpeg` CLI (testsrc2, encoded per codec).
2. **`show` crate:** model, protocol enums, geometry (rect mapping math), cue ops (add/move/duplicate/delete cue, next-slot), scene-from-cue, serde roundtrip, ts-rs export. Unit tests for each.
3. **Engine core:** winit app + wgpu device; outputs from `SetConfig` (create/move/close windows, Bound/Unbound); monitor list; compositor with test patterns + images; mapping to outputs. Headless render test: offscreen screen → mapping → output texture, assert pixels at known coords (split one screen across 2 outputs).
4. **Engine media:** player pool with refcount; hwaccel decode threads + plane upload (NV12/P010/BGRA/RGBA16); alpha blending; Loop/Once/HoldLast; audio via cpal; `Probe` + thumbnails. Decode tests on fixtures (frame count, pts monotonic, loop, alpha pixel sample from ProRes 4444).
5. **Engine buses + transitions:** PVW/PGM scenes, player resolution by `(screen, media, index)`, PVW cue-paused players start on Take, Take merge for undefined screens, Cut/Fade/Wipe only on changed screens, `TakeDone`. Tests: shared player identity across Take (same Arc), undefined screen untouched, explicit-empty screen goes black.
6. **Engine net:** axum WS (token), MJPEG preview endpoints, `Positions` 5 Hz.
7. **Tauri controller:** spawn sidecar with token, WS client with reconnect + resend state on engine restart, Show ownership, invoke commands (screen mgmt CRUD, media import via dialog, cue CRUD, load/take/transport), undo/redo, save/open/autosave.
8. **Frontend:** T1-style layout — Resource panel (media list with thumbs, test patterns), Canvas with PGM/PVW tabs (MJPEG `<img>` + draggable layer boxes overlay), Output Monitor, Property panel (layer params, transition), cue grid with group tabs, transport bar, Screen Management modal (Outputs tree + Add Output from monitor list, Screens list, Mapping and Layout editors with drag + numeric X/Y/W/H). Hotkeys Space / → / Cmd-Z.
9. **Packaging:** `tauri build` with engine as `externalBin`; bundle FFmpeg dylibs (macOS, fix rpaths) / DLLs (Windows).

### Verification
- `cargo test --workspace` (model, cue ops, mapping math, headless render pixels, decode, player identity across Take).
- `cd app && npm run tauri dev`, then manually: add two **Window** outputs + one Display output on second monitor; one 3840×1080 screen mapped half to each window; import `Background.png`-like image + an mp4; cue 1 = looping bg video + image, cue 2 = same bg video + ProRes 4444 alpha overlay; load cue 2 to PVW (PGM unchanged, overlay paused on first frame), Space → fade; bg loop does not restart, overlay starts on Take, alpha correct; cue touching only screen A leaves screen B untouched; 4× 4K layers hold 60 fps (engine fps in status); audio audible; kill engine process → controller restarts it and outputs return; force-quit UI → outputs keep playing; save, reopen, identical.
- Windows: same checklist on a Windows box before first show.
